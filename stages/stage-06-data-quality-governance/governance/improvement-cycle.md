# Data Quality Improvement Cycle

## Purpose

Data Quality Governance connects data quality monitoring with issue management and continuous improvement.

The purpose is to ensure that data quality problems are not only detected, but also managed, resolved, validated, and monitored over time.

## Improvement Cycle

The project follows this general cycle:

**Profile → Assess → Validate → Monitor → Identify Issue → Assign → Improve → Re-validate → Monitor**

### 1. Profile

Understand the structure, characteristics, and basic quality of the data.

### 2. Assess

Evaluate the data using defined Data Quality dimensions and rules.

### 3. Validate

Execute Data Quality Rules to identify violations.

### 4. Monitor

Track Data Quality results across multiple validation runs.

### 5. Identify Issue

Convert significant or relevant rule failures into Data Quality Issues.

### 6. Assign

Assign the issue to the appropriate responsible role or team.

### 7. Improve

Apply corrective and, where possible, preventive actions.

### 8. Re-validate

Run the relevant Data Quality Rules again to confirm that the issue has been resolved.

### 9. Monitor

Continue monitoring future runs to determine whether the issue has been resolved permanently or appears again.

## Connection to Previous Stages

This improvement cycle extends the work completed in the previous project stages:

- Stage 01 established data understanding through profiling.
- Stage 02 assessed data quality using defined dimensions and rules.
- Stage 03 documented data quality findings.
- Stage 04 established a reusable validation framework.
- Stage 05 introduced monitoring across validation runs.
- Stage 06 adds governance, ownership, issue management, prioritization, and continuous improvement.

## Continuous Improvement

Data Quality should be treated as an ongoing process rather than a one-time activity.

Monitoring results can identify new issues or recurring problems, which can then be managed through the governance process and followed by additional validation.
